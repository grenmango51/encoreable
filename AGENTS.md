# Encoreable

Analysis board for competitive Pokémon: restore a recorded battle at any turn in the real Showdown UI and play it forward for both sides. Primary inference target: `[Gen 9 Champions] VGC 2026 Reg M-C`, doubles. Known-team replay and branching also support the exact format/capability profiles in `docs/engineering.md` §2.8; this does not imply reconstruction or hidden-team inference for those formats.

## Before you start
- **Work on `main`.** Feature branches get merged into it; I also work on this from other devices, so `git pull` first.
- **Node 22.18+ is required and is not on the PATH on the Windows laptop.** In each new terminal: `$env:Path = "C:\Program Files\nodejs;" + $env:Path`. Then `npm install` once.
- **Commands, flags and layout are in `README.md`** ("Running it", "Layout", "Documentation"). Don't guess them.
- **Which doc answers what** is the Documentation table in `README.md`. `docs/engineering.md` is the engineering reference; the open/closed sheet plans are the current work lists.
- **Don't read `docs/evidence-open-sheets.md`, `docs/evidence-closed-sheets.md` or `docs/evidence-by-hand.md` whole.** They are 0.2–1.6 MB (the first two are generated by `npm run catalog`). Search them for the move, ability or item you need.

## Hard rules
- The Showdown simulator is never modified, and we never write damage, accuracy or turn-order logic. Showdown is the only source of truth (`docs/plan.md` §3).
- Showdown is pinned on purpose (`docs/engineering.md` §6.5). Upgrading it requires re-running the checks listed under "Upstream references" in `README.md`.
- `recordings/local/` cannot be regenerated. Never delete or rewrite those logs.

## Done means
- `npm run check` passes, and `npm run replay` still reproduces exactly.
- For inference changes: the relevant `npm run reconstruct` rungs from the plan you are working on pass.
- For extension changes: `npm run extension -- --check` passes.
- For anything visible: open it and look. A passing script is not proof the board looks right.

# Where new files go

Every path in this project already means something. Match the file to a row below and put it
there. `README.md` describes what each directory *is*; this file decides where a *new* file
belongs.

## The rule

**DO NOT ADD FILES TO ANY FOLDER IN A WAY THAT DOES NOT FOLLOW THE TABLE BELOW WITHOUT ASKING
THE USER DIRECTLY, ONE FILE AT A TIME. PLAN APPROVAL DOES NOT COUNT AS PERMISSION.** Approval
of a plan, a design, a task list, or a described approach is never approval to create a file
the table does not already place. Ask for that file, by name, on its own, and wait.

## The table

| A new… | goes in |
|---|---|
| Command a person runs | `scripts/local-<name>.mjs` — plus one `package.json` script and one `<name>.bat` at the root |
| Piece of Node machinery two or more commands share | `scripts/lib/<name>.mjs` |
| Script that runs in the browser, served over HTTP | `scripts/client/<name>.js` — never runnable with `node` |
| Code that runs inside the Showdown server process | `scripts/server/<name>.js` — CommonJS, copied into `runtime/config/` by provisioning, never `.mjs` |
| Team or format fixture loaded by Node | `scripts/fixtures/<name>.js` — CommonJS, not ESM |
| Chrome extension code — a content script, the simulator Worker, the service worker, an extension page | `extension/src/<name>.js`, with `<name>.html` beside it for a page — bundled by `npm run extension`, never runnable with `node`; a new entry point is added to `ENTRIES` in `scripts/local-extension.mjs` and, if Chrome loads it, to `extension/manifest.json` |
| Browser stand-in for a Node built-in that reused `scripts/lib` code imports | `extension/src/node/<built-in>.js` |
| Check that proves the built extension against the Node reference | `extension/check/<name>.mjs` — Node, run by `npm run extension -- --check <name>`, named in `CHECKS` there |
| Built extension | `extension/dist/` — written by `npm run extension`, gitignored, never hand-edited |
| Battle our local server recorded, worth keeping | `recordings/local/<scripted, probes, self-play or branched>/<battleid>.log.json` — tracked, cannot be regenerated; `recordings/README.md` picks the folder |
| Input log rebuilt from a replay | `recordings/reconstructed/reconstructed-<replay name>.log.json` — written there by `npm run reconstruct` |
| Replay page saved from play.pokemonshowdown.com | `recordings/showdown/<full-sheets, mine-open, mine-closed, others-open or others-closed>/<name as downloaded>.html` |
| Replay known only by its link on replay.pokemonshowdown.com | the link's `.json`, as served, in the same folder as a page would go: `recordings/showdown/<folder>/<replay id>.json` |
| Battle video | `recordings/video/<tournament or champions>/` — gitignored; list it in that folder's `README.md` |
| Rendered replay page | `replays/` — written by the commands, gitignored, never hand-authored |
| What a command keeps between runs to skip work it already did | `.cache/<command>/` — written by that command, gitignored, safe to delete, never hand-edited |
| Local Showdown server file | `runtime/` — generated from `node_modules`, never edited by hand |
| Upstream client file | `vendor/` — a clone of someone else's repo, never edited |
| Explanation of a directory whose contents are not self-evident | `<that-directory>/README.md` |
| Document answering a question no document in `docs/` owns | `docs/<name>.md`, lowercase — first check whether it belongs *inside* one of those |
| Scratch file, experiment, probe, or one-off diagnostic | nowhere in this repo — use the session scratchpad and delete it; only a battle it recorded that is worth keeping goes to `recordings/local/probes/` |

## Extensions carry meaning

`.mjs` is a Node ES module. `.js` under `scripts/client/` is browser code. `.js` under
`scripts/fixtures/` and `scripts/server/` is CommonJS. `.js` under `extension/src/` is browser
code, bundled for Chrome; `.mjs` under `extension/check/` is Node. Picking the wrong one breaks
the file at load time, not at review time.

## Before adding anything

Ask whether the thing belongs in a file that already exists. A new command that is a variant of
an existing one is a flag, not a file. A new document that restates a section of an existing
one is an edit, not a file. This project has already had to merge four documents back into one.
