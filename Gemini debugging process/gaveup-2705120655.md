## 5. Root Cause Analysis: Why `both@spectator` Stalled & Why Fallback Rebuilds Cycled

### A. `speed.mjs` Failed to Read the `1.4` Speed Order Because `Staraptor` Flinched After `Fake Out` (`+3`)
At Turn 1 `1.4`, `speedRules()` (`scripts/lib/inference/speed.mjs`, lines 702–786) observes:
- `prefix.observedLine` = `|cant|p2b: Staraptor|flinch` $\implies$ `was = { kind: 'move', ident: 'p2b: Staraptor' }`.
- `cut.line` = `|move|p2a: Arbok|Switcheroo|p1b: Farigiraf` $\implies$ `got = { kind: 'move', ident: 'p2a: Arbok' }`.
- Because `Staraptor` flinched (`|cant|...|flinch`), the replay never prints a `|move|p2b: Staraptor|...` line in Turn 1, so `chosen()` returns `null` and `unseen = true` (`line 746`).

To identify `Staraptor`'s priority when `unseen === true`, `speedRules()` calls `between(item)` (`lines 741–745`):
```js
const before = x ? executed[executed.indexOf(ex) - 1] : null;
const a = before?.sort && before.sort.turn === S.turn && shown.get(before.action)?.on && !movedAfter(before.action, before.sort)
  ? before.sort.list.find(item => item.action === before.action) : null;
const between = item => !!a && a.order === x.order && a.priority === x.priority && item.priorities !== null
  && before.sort.list.find(it => it.action === item.action)?.priorities === item.priorities;
```
Here:
- `x` is `Arbok`'s `Switcheroo` (`order = 200, priority = 0`).
- `before` is the preceding executed action: `Incineroar`'s `Fake Out` (`order = 200, priority = +3`).
- Because **`a.priority === x.priority` (`3 === 0`) is `false`**, `between(item)` returns **`false`**!

Consequently, `opened(item, between)` returns `false`, `y` and `PO` evaluate to `null`, and **`speed.mjs` emits ZERO speed rules for `Staraptor-Mega >= Arbok`**!
- Mechanically, `Staraptor`'s moveset (`Close Combat`, `Dual Wingbeat`, `Tailwind`, `Protect`) contains only priority `0` and `+4` (`Protect`). Had `Staraptor` chosen `Protect` (`+4`), it would have acted *before* `Incineroar`'s `+3` `Fake Out`; taking `Fake Out` proves `Staraptor`'s chosen move had priority `<= +3`, which uniquely forces priority `0`!
- Because `speed.mjs` checked only `a.priority === x.priority` instead of bounding `P`'s moves with `priority <= a.priority`, `Arbok spe` remained `[0, 32]`, the guess (`Arbok spe = 32`) never moved (`unchanged = true`), and Rounds 1–4 in all 6 starts repeated `2 turns exact, 1 dice handed on` until `++level >= budgets.length` (`searches`).

### B. `fallback` `done`-Collision Blind Spot Skipped Binary-Searching `Arbok spe` (`infer.mjs` lines 761–816)
Because `1.4` is an order divergence (`order = true`) on a turn with an unseen move (`disputed.size > 0`), `fallback` first executes the `disputed` speed-pair block (`scripts/lib/inference/infer.mjs`, lines 761–786):
1. Pair 1 probes `[{Staraptor spe: 32}, {Arbok spe: 0}]` (lines 10, 34, 62, 122, 182, 246).
2. Because `Staraptor spe` was **already `32`** in `start` (`Staraptor 32/0/2/0/0/32` or `29/1/0/0/4/32`), `[{Staraptor spe: 32}, {Arbok spe: 0}]` produces the **exact same spread matrix** as the single-stat probe `[{Arbok spe: 0}]`.
3. `probe()` hashes that spread matrix into `done`, runs `rebuild()`, observes `stops at 0.22` (`'early'`), and **never writes `'early'` into `Arbok spe`'s `d.sides`** (unlike `tryValue`).
4. Immediately afterward, the single-stat `ends` loop (`lines 809–816`) calls `tryValue(Arbok spe, 0)`. Inside `probe()`, `done.has(signature(chosen))` is `true`, so `probe()` returns `null`, and `tryValue` returns `null` (`lines 746–747`).
5. Thus `ends = [null, 'same']` fails `if (!ends.includes('early') || !ends.includes('same')) continue;`, **completely skipping `halving` on `Arbok spe`**!

### C. Why Start 6 Stopped at 60/128 Rebuilds Without Ever Testing `Arbok spe` in `[1..15]`
In Start 6 (`widest` + `wide`, cap = `128` rebuilds, lines 243–329):

## 7. Single-View vs. Spectator Contrast & Architectural Takeaways

### Cross-View Behavior (`p2@p1`, `p1@p2`, `both@spectator`)
- **`p2@p1` and `both@spectator`**: Both infer Player 2 (`Arbok` and `Staraptor`), so both initialize `Arbok` at `Spe = 32` (`217` Scarfed) in both `default` and `usage` starts and immediately hit the Turn 1 `1.4` `speed.mjs` / `fallback` deadlock.
- **`p1@p2`**: In `slowest_gave_up.json`, `p1@p2` is also listed among the gave-up views (`1,090.7s` sweep entry, `stop: "searches"`, `limits: ["fallbackRebuilds", "probes", "searches"]`). Because `p2`'s spreads are known in `p1@p2`, `p1@p2` does not suffer from the unknown `Arbok` / `Staraptor` Turn 1 `1.4` speed inversion and therefore must have hit a separate stall later in the battle (not covered by the `both@spectator` trace).

### Architectural Takeaways
1. **Bound Unseen-Move Priority Using the Preceding Action (`scripts/lib/inference/speed.mjs`, lines 741–745)**:
   When `P` (`Staraptor`) flinched or was fully paralyzed (`unseen === true`) immediately after an executed action `before` (`Incineroar`'s `Fake Out` at `priority = +3`), any move of `P`'s with `priority > before.priority` (here `Protect` at `+4`) would have executed *before* `before`. Checking whether all of `P`'s moves with `priority <= before.priority` share `x.priority` (here `Close Combat`, `Dual Wingbeat`, and `Tailwind` are all `priority = 0`, matching `Arbok`'s `Switcheroo`) would prove `P`'s priority is `0` and emit `Staraptor-Mega >= Arbok`, cutting `Arbok spe` to `[0, 9]` on Round 1.
2. **Prevent `disputed` Pair Probes from Blocking Single-Stat Halving via `done` (`scripts/lib/inference/infer.mjs`, lines 761–816)**:
   When `order && disputed.size` probes `[{ ...da, value: top(da) }, { ...db, value: db.alive[0] }]` while `da.now === top(da)` (`Staraptor spe === 32`), the probe tests the exact spread vector of `[{ ...db, value: db.alive[0] }]` (`Arbok spe = 0`), adding its signature to `done` without recording `db.sides.set(db.alive[0], sideOf(got))`. Recording single-stat outcomes when `da` did not move (or reusing the recorded side in `tryValue` instead of returning `null` on `done`) would allow `halving` on `Arbok spe` (`0` = `'early'`, `32` = `'same'` $\to$ `16` $\to$ `8` $\to$ `4`), resolving `1.4` in ~3 fallback rebuilds.
