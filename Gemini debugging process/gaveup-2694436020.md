## 5. Why Single-View Inference Failed Across All Views (`p1@p2`, `p2@p1`, and `both@spectator`)

In many mimic benchmark matches, single-observer views (`p1@p2` or `p2@p1`) pass rapidly because exact integer HP on the observer's side decouples damage equations and exposes true stats. **In Match 2694436020, however, all three views failed with `GAVE UP`:**
- `p1@p2`: 50 rounds, 199 rebuilds, 172,646 probes, 1,922.9s -> `GAVE UP` (`stop = "searches"`).
- `p2@p1`: 38 rounds, 188 rebuilds, 207,085 probes, 1,953.8s -> `GAVE UP` (`stop = "searches"`).
- `both@spectator`: 46 rounds, 286 rebuilds, 404,906 probes, 3,927.9s -> `GAVE UP` (`stop = "searches"`).

### Mechanical Breakdown of the Universal Single-View Failure
1. **Reconstruction Requires Action-Level Protocol Equivalence**:
   - The inference engine (`inferSpreads` in `infer.mjs`) evaluates spread candidates by passing them to `reconstruct()` (`reconstruct.mjs`).
   - A candidate spread is only accepted if the reconstructed battle log matches the public protocol line-for-line up to allowable soft-noise lines.
   - On Turn 8, action index 8, the observed public protocol demands:
     ```text
     |move|p2a: Grimmsnarl|Spirit Break|p1a: Whimsicott
     ```
   - When the simulator instead produces:
     ```text
     |move|p2a: Grimmsnarl|Spirit Break|p2b: Garchomp
     ```
   - This constitutes an immediate hard failure (`gotHard !== wantHard`), stopping reconstruction at `turn 8, line 8`.

2. **Independence from Observer Channel / Percentage Decoupling**:
   - Whether the observer is Player 1 (Channel 1), Player 2 (Channel 2), or a Spectator (Channel 0), the action `|move|p2a: Grimmsnarl|Spirit Break|...` is an identical public protocol event.
   - Because the divergence is not a damage roll or an HP percentage rounding mismatch, having exact integer HP on either side provides zero diagnostic leverage to resolve the target difference.
   - Consequently, all three view pipelines entered identical fallback probing loops and exhausted their search budgets.

## 6. Spectator Search Pathology & Root Cause Analysis

### Root Cause 1: The Revival Blessing Mid-Turn Slot Population Conflict
The primary catalyst of the stall occurs on Turn 8 due to how `Revival Blessing` interacts with Showdown's choice submission and target validation:
1. **At Turn 8 Choice Submission**:
   - At the beginning of Turn 8, Player 1 has only one active Pokémon: `p1b: Pawmot` at position index 1.
   - Position index 0 (`p1a`) is empty (Whimsicott fainted on Turn 6).
   - Player 2's Grimmsnarl must submit a move choice for `Spirit Break`.
   - `Spirit Break` has `target: "normal"`, which belongs to `CHOOSABLE_TARGETS` (`['normal', 'any', 'adjacentFoe', 'adjacentAlly', 'adjacentAllyOrSelf']`).
2. **Target Enumeration in `targetOptions`**:
   - In `scripts/lib/reconstruct.mjs`:
     ```javascript
     const live = (side.foe?.active || []).map(p => !!p && !p.fainted);
     const options = [];
     for (let i = 0; i < Math.max(1, live.length); i++) {
       if (!live.length || live[i]) options.push(` +${i + 1}`);
     }
     ```
   - Because `side.foe.active[0]` is empty, `live[0]` is `false`, while `live[1]` (Pawmot) is `true`.
   - The live foe list generates only ` +2`.
   - Next, because `moveTarget !== 'adjacentFoe'` and doubles allows targeting an ally, `targetOptions` adds the ally (`p2b: Mega Garchomp Z`): ` -2`.
   - The observed replay action from the log had `target = 'p1a: Whimsicott'`, yielding `loc = +1`, which is prepended as `preferred`:
     ```javascript
     options = [' +1', ' +2', ' -2']
     ```
3. **Mid-Turn Execution vs Target Resolution**:
   - When Pawmot moves first under Tailwind, `Revival Blessing` revives Whimsicott and switches it into slot `p1a`.
   - Garchomp then moves and knocks out Pawmot with Earth Power.
   - When Grimmsnarl's turn arrives to execute `Spirit Break`:
     - If the simulator's variant selection or retargeting logic evaluates the target, or if `preferred` (`+1`) was redirected or variant-indexed, Showdown's `getTarget` / `getRandomTarget` routines must resolve where the move lands.
     - In the simulation run during inference, Grimmsnarl executed `Spirit Break` targeting `p2b: Garchomp` (its own ally) instead of `p1a: Whimsicott`.
