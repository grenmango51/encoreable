## 5. Root Cause Analysis: Why ALL Three Views Gave Up

### The Defect in `scripts/lib/reconstruct.mjs`
The reason all three views gave up is that the battle reconstruction engine **cannot reproduce past Turn 7 under any candidate spread** due to an erroneous assumption regarding `Revival Blessing` switch mechanics.

#### 1. Showdown's `Revival Blessing` Implementation
In Pokemon Showdown (`sim/battle.ts` line 2291):
```typescript
case "revivalblessing":
  action.pokemon.side.pokemonLeft++;
  if (action.target.position < action.pokemon.side.active.length) {
    this.queue.addChoice({
      choice: "instaswitch",
      pokemon: action.target,
      target: action.target
    });
  }
  action.target.fainted = false;
  // ... heals target to 50% HP ...
  this.add("-heal", action.target, action.target.getHealth, "[from] move: Revival Blessing");
  break;
```
Notice the condition: `if (action.target.position < action.pokemon.side.active.length)`.
- In Doubles, `side.active.length === 2`.
- `action.target.position` is the index of the revived Pokémon in `side.pokemon`.
- If the revived Pokémon was a lead (index 0 or 1), Showdown queues an `instaswitch` immediately during the turn.
- However, if the revived Pokémon was a benched Pokémon (index 2 or 3 in the party lineup), `action.target.position >= 2`. Showdown **DOES NOT** perform an `instaswitch`!
- The revived Pokémon is revived **on the bench**.
- When the turn ends and reaches `upkeep`, Showdown checks `faintMessages()` / `checkFainted()`. Seeing that slot `p1b` is empty and a legal Pokémon (Indeedee-F) is alive on the bench, Showdown issues a `forceSwitch` request to Player 1:
  `activeRequest.forceSwitch: [false, true]`.
- The player **must** respond with `>p1 pass, switch 3` to bring Indeedee-F onto the field.

#### 2. The Flawed Logic in `planSegment`
In `scripts/lib/reconstruct.mjs` (lines 125–144):
```javascript
// One revived into an empty active slot is switched in by the
// simulator itself, so its switch line answers no request.
let reviver = null;
let revived = null;

for (const [i, line] of segment.entries()) {
  const parts = line.split('|');
  const kind = parts[1];

  if (kind === '-heal' && tagsOf(line).from === 'move: Revival Blessing' && reviver) {
    const side = identSide(parts[2]);
    plan.forced[side].push({ slot: reviver.slot, name: identName(parts[2]) });
    revived = { side, name: identName(parts[2]) };
    reviver = null;
    continue;
  }
  if (kind === 'switch' && revived && identSide(parts[2]) === revived.side && identName(parts[2]) === revived.name) {
    revived = null;
    continue;
  }
```
Notice what happens:
1. When `-heal` from `Revival Blessing` is seen, it pushes `{ slot: 0, name: "Indeedee" }` to `plan.forced.p1`. This entry answers the in-turn `Revival Blessing` party-selection prompt.
2. Next, when the observed upkeep switch line appears:
   `|switch|p1b: Indeedee|Indeedee-F, L50, F|88/177`
   Lines 141–144 match `revived.name === 'Indeedee'`.
   Because the code falsely assumed that `"One revived into an empty active slot is switched in by the simulator itself, so its switch line answers no request"`, it sets `revived = null` and executes `continue`!
3. The switch line is **discarded** and never added to `plan.forced.p1`!

#### 3. What Happens in Replay Execution
When `reconstruct` simulates Turn 7:
1. Turn 7 starts: Pawmot uses Revival Blessing.
2. Showdown asks `forceSwitch: [true, false]`. `buildChoice` pops `{ slot: 0, name: "Indeedee" }` from `plan.forced.p1` and sends `>p1 switch 3, pass`. Showdown revives Indeedee-F on the bench.
3. Dragonite and Basculegion attack Pawmot.
4. Turn 7 ends, `battle.turn` becomes 8.
5. In `playThrough` (line 1350): `if (k >= 1 && battle.turn > k) break;` triggers because `battle.turn === 8 > 7`. Loop `k = 7` terminates.
6. Loop `k = 8` starts: Showdown is in `upkeep` waiting for the unfulfilled `forceSwitch: [false, true]` request.
7. `choiceFor(side, plans[8], state, notes)` is called. Because the switch was in the Turn 7 segment, `plans[8].forced.p1` has no forced switch entry.
8. Line 490 of `reconstruct.mjs`: `if (at < 0) return 'pass'`.
   `choiceFor` generates: `>p1 pass, pass`.
9. Showdown receives `>p1 pass, pass` and **rejects** it:
   `[Invalid choice] Can't pass: You need a Pokemon to take the place of Incineroar`.
10. `reconstruct.mjs` detects the rejection at line 1380:
    `state.unsatisfied = "turn 8: a choice was rejected - nothing advanced"`.
    The simulation halts with `badTurn = 8` (or divergence on Turn 7 dice).

#### 4. The Consequence for Inference
Because `reconstruct` is completely unable to verify past Turn 7:
- **No guess can ever pass**: Even if the inference tests the exact true Stat Points, `reconstruct` fails with a rejected choice at Turn 7/8.
- **Evidence is truncated at Turn 6**: The inference can never learn anything from Turns 7–10 (such as Pawmot surviving Last Respects at 10 HP, Dragonite's subsequent damage rolls, or Basculegion's Protect cycles).
- **All candidate spreads remain unresolvable**: What survives from Turns 1–6 is vast and indeterminate.
