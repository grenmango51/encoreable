## 5. Root Cause Analysis: Why Spectator Inference Gave Up

### 5.1 The Mimic AI Aiming Artifact & Accidental Self-Harm Redirection
In standard competitive Showdown play, the "Beat Up + Justified" strategy relies on an ally targeting its partner to stack Attack boosts.
In `scripts/lib/mimic.mjs`:
```javascript
aim(target, wanted, i) {
  const foe = this.side === 'p1' ? 'p2' : 'p1';
  const standing = side => this.battle[side].active.map((p, k) => (p && !p.fainted ? k : -1)).filter(k => k >= 0);
  if (wanted) {
    const at = this.battle[wanted.side].active.findIndex(p => p && !p.fainted && p.baseSpecies.baseSpecies === wanted.base);
    const ally = wanted.side === this.side;
    const fits = target === 'adjacentFoe' ? !ally : target === 'adjacentAlly' ? ally && at !== i : target === 'adjacentAllyOrSelf' ? ally : true;
    if (at >= 0 && fits) return ally ? -(at + 1) : at + 1;
  }
  if (target === 'adjacentAlly' || target === 'adjacentAllyOrSelf') {
    const ally = standing(this.side).find(k => k !== i);
    return ally !== undefined ? -(ally + 1) : target === 'adjacentAllyOrSelf' ? -(i + 1) : null;
  }
  const foes = standing(foe);
  return foes.length ? this.prng.sample(foes) + 1 : 1;
}
```
At the start of Turn 1, Player 2's active slots were `Pawmot` and `Maushold`. Absol was in the party.
When `MimicPlayer` evaluated Maushold's action, `wanted.base` was `'Absol'`. Because Absol was not active on the field, `this.battle.p2.active.findIndex(...)` returned `-1`. Because Beat Up's target is `'normal'` (not `'adjacentAlly'`), the solver fell back to `prng.sample(foes)`, inadvertently targeting P1's `Floette-Eternal`.
This AI aiming artifact forced the mimic battle into an unnatural Turn 1 state: 4 Beat Up strikes targeting a Mega-Evolving Fairy-type.

### 5.2 The Beat Up Mechanics & Party Base Attack Scaling Disconnect
Beat Up possesses unique mechanics in Pokémon Showdown:
1. It strikes once for each conscious, status-free party member (4 strikes on Turn 1).
2. For strike $k$, the move's base power is calculated directly from party member $k$'s base Attack:
   $$\text{Base Power}_k = \left\lfloor \frac{\text{Base Attack}_k}{10} \right\rfloor + 5$$
   - Strike 1 (Party Member 0: Ninetales-Alola, Base Atk 67) $\to \text{BP} = 11$
   - Strike 2 (Party Member 1: Absol, Base Atk 130) $\to \text{BP} = 18$
   - Strike 3 (Party Member 3: Pawmot, Base Atk 115) $\to \text{BP} = 16$
   - Strike 4 (Party Member 4: Maushold-Four, Base Atk 75) $\to \text{BP} = 12$
3. Damage calculation uses the user's (`Maushold`) Attack stat against the target's (`Floette-Mega`) Defense stat.
4. On a spectator screen, exact damage numbers are hidden behind integer percentages (`98/100`, `96/100`, `95/100`, `92/100`).

In `infer.mjs`, when fallback encounters a damage mismatch on Turn 1:
```

```
Fallback attempts to solve the discrepancy by sweeping through `Maushold`'s Attack Stat Points (from 32 down to 0).
As recorded in lines 407–428 of the cluster trace:

- At `Maushold atk 18`, damage stepped immediately to `97/100`.
- At `Maushold atk 9`, damage was still `97/100`.
**The expected value `98/100` was mathematically impossible to produce by mutating Maushold's Attack alone!** The damage of Strike 1 was dominated by Ninetales's Base Attack and Floette's Defense and Max HP, completely unfixable through Maushold's SP.

### 5.4 The Speed Reordering Threshold Gate (Floette Spe 102 vs Maushold Spe 111)
