### The Failure of `choose` (Round 10)
In `infer.mjs`, the candidate selection function `choose(n, cond)` performs recursive branch-and-bound search across the sequence of seen Pokémon (`seq.length = 7`):
- Budget per round: `tries = 32 * S * W` (at `S=1, W=1`, exactly **32 tries**).
- Every branch step consumes tries:
  - 1 try for pinning HP/Def/SpD (`keyed`)
  - 1 try for pinning the full spread (`narrowed`)
  - 1 try at the leaf to run `evidencePass({ exact: true })`
- For a tree of depth 7, a single path from root to leaf consumes 14–15 tries.
- With only 32 tries available, `choose` can explore at most **2 candidate combinations** across all 7 Pokémon.
- Because of percentage quantization and multi-variable coupling on Turn 4, the initial heuristic aims fail to satisfy every verified turn exact.
- `choose` exhausts its 32 tries, hits limit `guessTries`, and returns `null`.
- Consequently:
  - `exact = null`
  - `pins = null`
  - No exact proofs or dice pins are handed to the next round.
  - The next round picks each Pokémon's spread **independently** using `closestSpread(kn)`.

### The Oscillation Loop and Fallback Thrashing (Rounds 6–12)

- In `fallback`:

  - Fallback tests single-stat variations: Excadrill HP 0 reaches Line 4.10 (`|-damage|p1a: Incineroar|32/100, got 30/100`), which is further than Line 4.8.
  - Fallback adopts Excadrill HP 0 as `ahead`, holding it for Round 12.

- Because Line 4.10 previously failed in Round 7, `again` is `true` again!
