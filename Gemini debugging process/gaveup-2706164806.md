## 5. Root Cause Analysis: Why All Views Stalled at `5.8` & Why Fallback Rebuilds Cycled

### A. Deterministic Reconstruction Bug: `planSegment` Drops `[from] lockedmove` After `Encore` (`scripts/lib/reconstruct.mjs`)
This match did **not** stall on Stat Points, damage rolls, or HP rounding — it stalled on a **parser/planner bug in `scripts/lib/reconstruct.mjs` (`planSegment`, lines 170–193)** when `Encore` lands on a Pokémon during the execution turn of a two-turn charge move (`Electro Shot`):

```js
    if (kind === '-start' && /Encore$/.test(parts[3] || '')) {
      encored.add(parts[2]);
      continue;
    }

    if (kind === 'move') {
      if (toID(parts[3]) === 'revivalblessing') reviver = { slot: identSlot(parts[2]) };
      if (encored.has(parts[2])) continue;          // <-- BUG: runs BEFORE checking lockedmove!
      const from = tagsOf(line).from;
      // ... `lockedmove` is the exception ...
      if (from && from !== 'lockedmove') continue;
```

On Turn 5, the observed log emits:
1. `|-start|p1b: Archaludon|Encore` $\to$ `encored.add('p1b: Archaludon')` (line 171).
2. `|move|p1b: Archaludon|Electro Shot|p2b: Kommo-o|[from] lockedmove` $\to$ **dropped by `if (encored.has(parts[2])) continue;` on line 177!**

This single early `continue` triggers a fatal two-part chain reaction:
1. **`recoverChargeTargets(plans)` Fails to Recover Turn 4's Target (`reconstruct.mjs` lines 208–225)**:
   On Turn 4, `Archaludon`'s charge line (`|move|p1b: Archaludon|Electro Shot||[still]`) leaves `plans[4].actions.p1[1] = { moveid: 'electroshot', target: null, needsTarget: true }`. `recoverChargeTargets` scans Turn 5 for `plans[5].actions.p1[1]` to copy `target: 'p2b: Kommo-o'` and set `action.landsOn = 5`. Because `plans[5].actions.p1[1]` is `undefined`, **`plans[4].actions.p1[1].target` remains `null` and `landsOn` remains `undefined`**.
2. **Turn 4 Always Defaults to `+1` (`Whimsicott`) and `carriedInto(plans, 5)` Is Blind to Turn 4**:

## 7. Cross-View Failure & Architectural Takeaways

1. **Why This Is a Pure Reconstruction Bug (`reconstruct.mjs`, Line 177)**:
   Unlike spectator-only parity or HP-rounding deadlocks, `mimic:gen9championsvgc2026regmcbo3-2706164806` failed identically in **`p1@p2`**, **`p2@p1`**, and **`both@spectator`** because `planSegment` (`scripts/lib/reconstruct.mjs` line 177) checked `if (encored.has(parts[2])) continue;` *before* checking `const from = tagsOf(line).from;` (`from === 'lockedmove'`).
   - When a Pokémon is Encored on the execution turn of a two-turn charge move (`Electro Shot`, `Solar Beam`, `Meteor Beam`, `Sky Attack`, `Freeze Shock`, `Ice Burn`, `Skull Bash`, `Razor Wind`, `Bounce`, `Dig`, `Dive`, `Fly`, `Phantom Force`, `Shadow Force`, `Sky Drop`, `Geomancy`), Showdown still executes the already-charged `|[from] lockedmove` attack at the target chosen on the **previous** turn.
   - Dropping that `|move|...|...|[from] lockedmove` line in `planSegment` breaks both `recoverChargeTargets(plans)` (leaving `preferred = null` on the charge turn) and `carriedInto(plans, t)` (leaving `landsOn` unset so `reconstruct` can never revisit the charge turn's target choice when the execution turn diverges).

2. **Exact Fix (`scripts/lib/reconstruct.mjs` Line 177)**:
   In `planSegment`, do **not** skip a `|move|` line under `encored.has(parts[2])` when `tagsOf(line).from === 'lockedmove'`:
   ```js
   const from = tagsOf(line).from;
   if (encored.has(parts[2]) && from !== 'lockedmove') continue;
   ```
   With that single condition, `plans[5].actions.p1[1]` preserves `{ moveid: 'electroshot', target: 'p2b: Kommo-o', needsTarget: true }`, `recoverChargeTargets(plans)` immediately sets Turn 4's `preferred` target to `+2` (`p2b: Kommo-o`) and `landsOn = 5`, and `5.8` resolves cleanly on the very first pass across all three views (`p1@p2`, `p2@p1`, and `both@spectator`).

3. **Collateral Benefit Across the Corpus**:
   Any VGC match in `slowest_gave_up.json` where `Whimsicott` (or another `Encore` user) Encores an `Electro Shot` / `Meteor Beam` / `Solar Beam` user on its execution turn will currently suffer the exact same false `carriedInto = []` stall and fail across all three views (`p1@p2`, `p2@p1`, `both@spectator`). Fixing `encored.has(parts[2]) && from !== 'lockedmove'` eliminates this entire class of cross-view give-ups cleanly per mechanism (Rule 3: one hook per mechanism, never per move).
